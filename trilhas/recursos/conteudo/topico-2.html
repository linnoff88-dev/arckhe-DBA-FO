Instância

Estruturas em memória (SGA, PGA) e processos que gerenciam o acesso aos dados. Existe apenas enquanto o banco está rodando.

Database

Arquivos físicos no disco que armazenam os dados, metadados e logs. Persistem mesmo quando o banco está desligado.

Processos de Background

🔄

PMON - Process Monitor

  • Detecta processos falhos
  • Libera recursos de sessões mortas
  • Faz rollback de transações incompletas
  • Registra instância no listener
🛠️

SMON - System Monitor

  • Recovery na inicializaçêo (instance recovery)
  • Limpa segmentos temporários
  • Coalece espaços livres em tablespaces
  • Recupera transações mortas
💿

DBWn - Database Writer

  • Escreve blocos sujos (dirty blocks) para disco
  • Escreve em checkpoints
  • Quando buffer cache está cheio
  • Múltiplos processos: DBW0..DBW9, DBWa..DBWj
📝

LGWR - Log Writer

  • Escreve redo log buffer para redo log files
  • Escreve em COMMIT
  • A cada 3 segundos
  • Quando buffer está 1/3 cheio
✅

CKPT - Checkpoint

  • Atualiza headers dos datafiles
  • Atualiza control files
  • Sinaliza DBWn para escrever dirty blocks
  • Reduz tempo de recovery
📦

ARCn - Archiver

  • Copia redo logs para archive logs
  • Apenas em ARCHIVELOG mode
  • Essencial para backups completos
  • Múltiplos processos: ARC0..ARC9, ARCa..ARCt
📁

Fluxo de Operações

Fluxo de uma Transaçêo (UPDATE)

1. User Process executa: UPDATE employees SET salary = 5000 WHERE id = 123;

2. Server Process:
   ┌─────────────────────────────────────────────────────────┐
   │ ① Verifica se bloco está no DB Buffer Cache             │
   │    • Se SIM → lê da memória (logical read)              │
   │    • Se NêO → lê do datafile (physical read)            │
   └─────────────────────────────────────────────────────────┘
                          ↓
   ┌─────────────────────────────────────────────────────────┐
   │ ② Gera UNDO entry (valor antigo) no Undo Segment       │
   │    • Permite ROLLBACK                                   │
   │    • Read consistency para outras sessões               │
   └─────────────────────────────────────────────────────────┘
                          ↓
   ┌─────────────────────────────────────────────────────────┐
   │ ③ Gera REDO entry no Redo Log Buffer                   │
   │    • Registra a mudança (change vector)                 │
   │    • Protege contra falhas                              │
   └─────────────────────────────────────────────────────────┘
                          ↓
   ┌─────────────────────────────────────────────────────────┐
   │ ④ Atualiza bloco no DB Buffer Cache                    │
   │    • Bloco agora é "dirty" (modificado)                 │
   │    • Ainda NêO está no disco                            │
   └─────────────────────────────────────────────────────────┘

3. User executa: COMMIT;

   ┌─────────────────────────────────────────────────────────┐
   │ ⑤ LGWR escreve Redo Log Buffer → Redo Log Files        │
   │    • SYNC write (aguarda confirmaçêo do OS)             │
   │    • Transaçêo é DURÁVEL após este ponto                │
   └─────────────────────────────────────────────────────────┘
                          ↓
   ┌─────────────────────────────────────────────────────────┐
   │ ⑥ Server Process confirma COMMIT ao usuário             │
   │    • "Commit complete"                                  │
   └─────────────────────────────────────────────────────────┘

4. Em background (assíncrono):

   ┌─────────────────────────────────────────────────────────┐
   │ ⑦ DBWn escreve dirty blocks → Data Files               │
   │    • Acontece em checkpoints                            │
   │    • Ou quando buffer cache está cheio                  │
   │    • NêO bloqueia o COMMIT                              │
   └─────────────────────────────────────────────────────────┘

IMPORTANTE:
- COMMIT força LGWR a escrever (redo logs SEMPRE antes de retornar)
- COMMIT NêO força DBWn (datafiles escritos depois, de forma lazy)
- Recovery usa redo logs para replicar mudanças nêo escritas em datafiles
